# Shopping List API

A simple REST API for managing a shopping list.

The application is built using **Node.js** and **TypeScript** and stores shopping list items in memory. Users can interact with the application through API requests using tools such as **Postman**.

---

## Features

The Shopping List API supports:

* Create a shopping list item
* Get all shopping list items
* Get a single shopping list item by ID
* Update an item's name
* Update an item's quantity
* Update an item's status
* Update multiple fields at once
* Delete a shopping list item
* Input validation
* Error handling
* Consistent JSON responses
* In-memory data storage

---

## Technologies Used

* Node.js
* TypeScript
* Node.js HTTP module
* Postman

# API Endpoints

| Method | Endpoint     | Description       |
| ------ | ------------ | ----------------- |
| POST   | `/items`     | Create a new item |
| GET    | `/items`     | Get all items     |
| GET    | `/items/:id` | Get a single item |
| PUT    | `/items/:id` | Update an item    |
| DELETE | `/items/:id` | Delete an item    |

---

# Shopping List Item

Each shopping list item has the following structure:

```json
{
  "id": 1,
  "name": "Milk",
  "quantity": 2,
  "status": "pending"
}
```

### Fields

| Field      | Type   | Description                                     |
| ---------- | ------ | ----------------------------------------------- |
| `id`       | number | Unique ID automatically generated by the server |
| `name`     | string | Name of the shopping item                       |
| `quantity` | number | Quantity required                               |
| `status`   | string | `pending` or `completed`                        |

The `id` is automatically generated and should not be supplied when creating an item.


### Request Body

The API allows any combination of:

* `name`
* `quantity`
* `status`

At least one field must be provided.

Deletes a shopping list item by ID.

### Request

```http
DELETE /items/:id
```

### Example


**404 Not Found**

```json
{
  "error": "Item not found"
}
```

# Validation

The API validates incoming requests before creating or updating items.

## Name Validation

The name must be a non-empty string.

### Invalid Request

```json
{
  "name": "",
  "quantity": 2,
  "status": "pending"
}
```

### Response

**400 Bad Request**

```json
{
  "error": "name must be a non-empty string"
}
```

---

## Quantity Validation

The quantity must be a number greater than `0`.

### Invalid Request

```json
{
  "name": "Milk",
  "quantity": 0,
  "status": "pending"
}
```

### Response

**400 Bad Request**

```json
{
  "error": "quantity must be a number greater than 0"
}
```

Negative quantities are also invalid:

```json
{
  "name": "Milk",
  "quantity": -2,
  "status": "pending"
}
```

---

## Status Validation

The status must be either:

```text
pending
```

or:

```text
completed
```

### Invalid Request

```json
{
  "name": "Milk",
  "quantity": 2,
  "status": "bought"
}
```

### Response

**400 Bad Request**

```json
{
  "error": "status must be either pending or completed"
}
```

---

## Missing Fields

When creating an item, `name`, `quantity`, and `status` are required.

### Invalid Request

```json
{
  "name": "Milk"
}
```

### Response

**400 Bad Request**

```json
{
  "error": "name, quantity and status are required"
}
```

---

## Empty Update

When updating an item, at least one field must be supplied.

### Invalid Request

```json
{}
```

### Response

**400 Bad Request**

```json
{
  "error": "At least one field is required"
}
```

---

## Invalid JSON

If an invalid JSON request body is sent:

### Example

```text
{
  "name": "Milk",
```

### Response

**400 Bad Request**

```json
{
  "error": "Invalid JSON request body"
}
```

# HTTP Status Codes

The API uses the following HTTP status codes:

| Status Code       | Description                         |
| ----------------- | ----------------------------------- |
| `200 OK`          | Request completed successfully      |
| `201 Created`     | A new item was successfully created |
| `204 No Content`  | Item was successfully deleted       |
| `400 Bad Request` | Invalid request or validation error |
| `404 Not Found`   | Item or route does not exist        |

---

# Error Response Format

Errors use a consistent JSON structure:

```json
{
  "error": "Error message"
}
```

For example:

```json
{
  "error": "Item not found"
}
```

# Data Storage

The application currently uses **in-memory storage**.

Shopping list items are stored in an array while the server is running.

For example:

```ts
let shoppingListsItems: ShoppingListItem[] = [];
```

This means that all data will be lost when the server is stopped or restarted.

A database could be added in a future version to permanently store the shopping list items.

A typical user workflow could be:

### 1. Add Milk

```json
{
  "name": "Milk",
  "quantity": 1,
  "status": "pending"
}
```

### 2. Realise You Need Two Litres

```json
{
  "quantity": 2
}
```

```json

  "status": "completed"
}
```

```text
DELETE /items/2
```

This demonstrates how the API can be used to manage a real shopping list from creation through completion.
